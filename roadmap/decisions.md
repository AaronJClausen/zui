# Decisions

What the owner settled, and what is still open. A decision names the item
that raised it.

## Made

| Decision | Outcome |
|---|---|
| The frame boundary | the cornerstone: a record in at `beginFrame`, a frame out of `endFrame` |
| The design system (`11-polish:13-design-vocabulary` to `11-polish:23-design-workbench`) | settled by the owner after a brainstorm: a design system (SPEC.md §18) that makes an accessible, coherent app the easy path, replacing the default skin (`11-polish:05-default-skin`, retired) and turning `11-polish:08-zui-themes` into designs, queued ahead of the rest of stage 11. Contrast is solved to APCA and also guaranteed at WCAG 2 AA, AAA in high contrast. A design that fails a target at comptime is a compile error with the lightness that passes; a color that arrives at run time, the user's or the system's, is repaired and reported, never fatal. The maker of tokens is a module, `zui_design`; the vocabulary it, `zui_widgets` and `zui_themes` all name (roles, tiers, `Design`, `Tokens`, the appearance contract) is the core's, since modules cannot import one another (SPEC.md §3.3); putting it in `zui_design` would have left `zui_widgets` unable to name it. The corner size of no radius is `square`, the owner's `pointy` |
| Color math in `zui_design` (`11-polish:14-zui-design`) | decided by measuring, as the item's plan asked: `zui_design` carries the OKLab conversions it needs in its own directory, over `zui.design.Oklch`, rather than taking them from the application, since a module cannot import `zui_color` (SPEC.md §3.3). Type-checking a design resolved at comptime, every color included, costs 0.05 s over the same check without it |
| Corner clamping and lowering in every context (`11-polish:16-corner-shapes`) | accepted by the owner: emission clamps every radius and reports every lowered shape even when the renderer declares only `round`, as SPEC.md §18.7 says, rather than compiling both out there. Square corners skip both by one test of the radii's bits; with that, the instruction counts grow at most +0.78% (3000 cells, endFrame) and +0.35% on 4096 boxes' declaration, within CI's 2% gate |
| A surface the platform takes away (`10-reach:06-platform-owned-loop`) | part of `10-reach:06-platform-owned-loop`'s design, settled by the owner: `suspendSurfaces` and `resumeSurfaces` detach and re-attach every window's surface through the renderer's `zuiDetachSurface` and `zuiAttachSurface`, so the renderer lets go of what it keeps for each while it, the contexts and the application live on; not left for the Android host. It replaced an earlier choice, `suspendSurface` then a fresh `start(surface)`, which would have remade the renderer and the text, when the calls `10-reach:05-many-windows` built already drop and take a surface |
| Who owns the loop (`10-reach:06-platform-owned-loop`) | settled by the owner, after two prototypes: one non-blocking `step` and three loops over it. A host declares at most one loop call: `zuiWait`, and `run` pulls the loop; `zuiRun(io, window, driver)`, and the platform pushes it through a `zui.Driver`; or neither, and the application's own loop steps a `zui_app.Session`. It took option 3 (one step, `zuiWait` kept where a host may block) and added the stepped host, so a game engine or an editor that owns its loop and window has a contract too; option 2, push only, would have changed every host and still left that case out. The other prototype made `std.Io` the loop: `zui_app` waits on a futex through its `Io`, and a platform that calls back steps an `Io` that suspends the loop on a stack of its own, a fiber or, in a browser, JS Promise Integration. Not taken: on such an `Io` a loop asked for a frame `.immediately` never returns control to the platform; the application's tasks have nowhere to run on it; zui would own stack-switching assembly; and its test runs on neither Windows nor ThreadSanitizer. What it found stands: under JSPI, `zui_app`'s own loop ran on a page's main thread, in Node 26, with every callback returning; `Io.Dispatch` resumes a fiber off the main thread, so it cannot hold AppKit's loop; and `std.Io` has no wait on a descriptor, so a host that polls one (Wayland, X11) keeps `zuiWait`. Zig 0.17.1 changes none of this |
| The turn after `zuiWait` (`10-reach:06-platform-owned-loop`) | stays due for an application with one window, since a host's wait may end for a repaint its record does not show; measured before deciding: judging that turn too saved one idle frame in ten seconds on the Wayland host and none on raylib, with no change while busy |

| Time | an instant in the record, not a delta (`02-frame-record:04-record-parameters`) |
| Replay | one `beginFrame`; a record with deliveries is a replay |
| `endFrame` | always returns a frame; limits are diagnostics (`02-frame-record:06-end-frame-always-returns`) |
| Render commands | generated from what the renderer declares; the rest lowered (`03-contracts:01-renderer-contract`) |
| Contract members | all `zui`-prefixed; unknown ones are compile errors |
| Static styles | approved: pointers to comptime configs, measured against the declaration budget (`06-text-and-layout:03-static-styles`) |

| Aspect ratio (`06-text-and-layout:08-aspect-ratio-and-natural-sizes`) | a height rule, `.aspectRatio(r)`, not a `Layout` field, which made every layout eight bytes larger and declaration 6.6% slower; neither stretched nor grown by its parent; on a width, or not positive, the content's size |
| Wrap (`06-text-and-layout:12-wrap`) | `ui.wrapChildren()` after a row's `open`, gated by `features.flex_wrap` with a compile error, not a `Layout.wrap` field, whose value is not known at compile time and which would make `Layout` four bytes larger; a column ignores it; lines break at each child's size before free space, then grow and shrink as rows; lines are as tall as their tallest child and `child_gap` apart; `child_alignment.y` places the lines and each child in its line; dividers between a line's children and between lines |
| Right-to-left layout (`06-text-and-layout:11-right-to-left`) | `Layout.mirrored: zui.Mirrored` (`.inherit`, `.yes`, `.no`), one byte rather than a `?bool`, which would make every `Layout` four bytes larger; inherited, the root's from the environment's `direction`; a mirrored or `right_to_left` element, not both, reflects its children across its box, so padding's `left` is the start side, alignment and floating anchors and offsets mirror, and a text's `.start` and `.end` swap; `right_to_left` covers the element's own children only, as `row-reverse`; a reversed scroller's offset grows to the left and takes the wheel's physical delta reversed; positions and borders stay physical; found by the position pass, which starts again mirroring at the first parent that mirrors, so other frames pay nothing |
| Floating options (`06-text-and-layout:10-floating-options`) | `capture = false` gives the floating element no hit region of its own, while interactive elements inside it keep theirs; `.clip = .target` cuts it off where its target's children are, merged with its own clip into one pair pushed in its layer before it draws; a later target places the subtree again after pass 6, in declaration order, and a target inside the subtree falls back to the parent; `capture` and `clip` are copied into the element's flags, so emission reads no floating config for other elements |
| A border inside its element's clip (`06-text-and-layout:10-floating-options`) | emitted before the element's own `clip_end`, which leaves it whole since it lies in the element's box, so a floating element's merged clip also cuts off its border with one clip pair |
| Effects (`08-effects:01-gradients-shadows-glow`) | `Element.effects: ?*const zui.Effects`, copied when declared, not a value in `Element` (interactive boxes' declaration +22%) or `Decoration` (every decorated element copies it), and not in `Style` (+3.5% of the static box tree's declaration); in the shape of the decoration's corners; painted shadow, background, gradient; a gradient in OKLab along a line through the center, long enough that the far corners take its ends; a shadow culled by what it paints; bounded by `limits.max_effects`; a frame without effects is emitted by a walk that never looks for them |
| Dividers (`06-text-and-layout:09-dividers-and-decorated-images`) | `Border.between_children`, emitted as `rectangle` commands in the border's color, so no renderer breaks; centered in the gap, spanning the element inside its widths; inside the element's clip, after its children and before its border; a border of zero widths emits no `border` command |
| Images' tint and corner radius (`06-text-and-layout:09-dividers-and-decorated-images`) | declared on `Ui.Image` and carried by the `image` command with defaults (white, square), so existing renderers and their tests still compile; drawing them is the backends' (`06-text-and-layout:13-image-tint-and-corners`) |
| Drawing images' tint and corner radius (`06-text-and-layout:13-image-tint-and-corners`) | the tint multiplies the texels as the vertex color; a rounded image is a fan of textured triangles from its center, each corner with its own radius, in the raylib renderer too, whose rectangles keep raylib's one radius; the renderer suite checks the tinted color at the image's center and the background just inside two of its corners |
| Natural sizes (`06-text-and-layout:08-aspect-ratio-and-natural-sizes`) | `Ui.Image` is the declaration's type, apart from the `image` command; a natural size is the content inside the padding, may shrink in a narrower parent, and gives the height its proportions unless the height has a rule of its own |
| A grow basis (`06-text-and-layout:07-grow-basis`) | a rule, `grow_from_min`, not a `basis` field, which would cost declaration; never narrower than the content's minimum, the rest shared by weight |
| Config references (`06-text-and-layout:03-static-styles`) | pointers in element storage, the default layout one constant; an element's own `layout` or `decoration` replaces the style's whole |
| Budgets | as in SPEC.md §20.2, judged in benchmarking mode (Turbo Boost off, the `performance` governor) from after the audit's `06-text-and-layout:18-string-cache-keys-apart`: the box tree < 125 µs and its declaration < 69 µs, warm text < 150 µs, each the earlier turbo-on budget × 1.25 |
| Where the contracts live | in the `zui` repo |
| Native hosts | one package, `zui_host` in `hosts/native/`, one directory per OS |
| Who orchestrates | the host, through one contract; adapters for libraries that own their window (`03-contracts:06-raylib-adapter-host`) |
| Signals | lifecycle events; uncatchable signals are not representable |
| Input | an ordered event log with host instants, many pointers (`02-frame-record:05-input-event-log`) |
| Gesture arbitration | elements declare what they accept; one rule, by motion component (`07-gestures:01-gesture-arbitration`) |
| How a frame's semantics reach a host (`09-seeing-the-ui:02-semantics-and-accessibility`) | an optional host call, `zuiSemantics(window, nodes) SemanticsDropped`, which `zui_app` makes on the UI thread between `endFrame` and submission, into room the window opened with (`WindowOptions.semantics`, sized from `Config.limits`); not a field of `HostRequests`, which every `zuiApply` compares, nor a generic call taking the whole frame |
| How a host holds many windows (`10-reach:05-many-windows`) | the Windows host is one type, `.many`, with `Host.max_windows = 4` fixed slots in every application, settled by the owner; a generic `HostWith(.{ .max_windows })` that pays only for what is declared was the other option |
| When `zui_app.run` returns with many windows (`10-reach:05-many-windows`) | once the last window has closed, settled by the owner; an application that wants closing `.main` to quit closes the rest in `zuiWindowClosed`. Returning when `.main` closes was the other option |
| When a window's context is made (`10-reach:05-many-windows`) | when the window opens, allocated with `gpa` as `init` makes the first, settled by the owner; reserving every context at `start` was the other option |

| How a renderer learns of windows (`10-reach:05-many-windows`) | `zuiAttachSurface` and `zuiDetachSurface`, optional and declared together, on the thread that submits, settled by the owner; attaching a surface lazily at its first submit was the other option, which would turn a failure into a render error that ends the run |
| How the hooks name the window (`10-reach:05-many-windows`) | every hook of the windowed form takes `window: zui.WindowId`, settled by the owner; a `zui_app.Window(App)` value in place of `ui` was the other option |
| A text field's Value pattern (`09-seeing-the-ui:02-semantics-and-accessibility`) | read: its `SetValue` fails with `UIA_E_INVALIDOPERATION`, since zui has no action that replaces text, but an enabled text field reports `IsReadOnly` false, since it is typed into from the keyboard and Narrator would otherwise call it read only; a combo box's Value is read-only |
| A custom recognizer's decision lands a frame late (`07-gestures:01-gesture-arbitration`, open decision 1) | accepted: `claim` and `decline` apply at the next `beginFrame`, and a declined pointer is arbitrated over all its motion since the press, so nothing is lost; the lasso against a map's pan passes with it |
| Custom recognizers (`07-gestures:01-gesture-arbitration`) | an element with `custom` holds each pointer pressed on it from every built-in gesture until it decides; `pointerEvents(id)` is an iterator, `zui.PointerEvents`, over the frame's events of the pointers it holds; a claimed pointer takes the press from what it pressed and is never a tap; one released undecided is a tap; the lasso is `zui_widgets.Widgets.lasso`, a pen drawing and every other pointer declined |
| Momentum (`07-gestures:01-gesture-arbitration`) | a pan released faster than 50 units a second over its last 0.1 s coasts on its axes, slowing exponentially with a time constant of 0.325 s, moved to each record's `now` before its events through the pan's path; it stops below 10 units a second, at a scroll container's end, under a press, or when its element was not declared; it asks for frames 1/120 s apart; at most `max_input_contacts` elements coast, and a fling beyond them is reported on that limit |
| Long press and double tap (`07-gestures:01-gesture-arbitration`) | timed from the events' instants against the record's `now`, setting the next frame's deadline: a long press after 0.5 s held within the slop, which is not a tap; a double tap within 0.3 s of the first tap's release, whose single tap is clicked only when that window passes; `doubleTapped(id)`, which SPEC.md lacked; `navigated` returns `zui.NavigationDirection`, since `Direction` has no up or left; `dismissed` while the element or one in its focus scope is focused; `contextRequested`, `dismissed`, `adjusted` and `navigated` need no feature, `doubleTapped` needs `features.gestures` |
| Zoom (`07-gestures:01-gesture-arbitration`) | a second pointer pressed while another is down, both inside an element that accepts zoom, makes the pair zoom the innermost such element, taking both pointers from what they pressed or panned; `scale`, `rotation` (clockwise) and the centroid's `translation` are summed over the frame, `pivot` is where the centroid ended; the pointer left when one lifts pans the element if it pans |
| Pans (`07-gestures:01-gesture-arbitration`) | past a touch slop of 8 layout units from the press, the axis locks to the larger component and the innermost region under the press that pans on it with room to move takes the pointer until it lifts, both axes if it pans on both; any other element it pressed loses the press; a scroll container pans on its scrolled axes with touch and pen only, since the mouse has the wheel, unless it declares `pan`, which takes every pointer; declaring a gesture makes an element interactive; `Element.gestures` is ignored without `features.gestures` rather than failing to compile, so widgets declare gestures for every context; `manipulation` reports pans and the wheel, scroll containers included, `translation` moving content with the pointer |
| Drag and drop (`07-gestures:02-drag-and-drop`) | a source declares `Gestures.drag` and takes a pointer past the slop on the axes no region around it pans on for that pointer, after any region inside it that pans; `startDrag` gives the payload, in the state table under the source as `DragPayload(T)`, or starts the drag with a pointer still pressed on the source, which is how a long press or a recognizer lifts it; the payload is kept while the drag lasts, the source may go undeclared; a target is any element with a hit region the hit test at the pointer passes through; `draggedOver`, which SPEC.md lacked, shows a drop target before the release; a drag released in its starting record, before it had a payload, or cancelled, drops nothing |

| How the tour's tasks run in the browser's worker (`09-seeing-the-ui:04-demo-in-browser`) | on an `Io` of the worker's own, `SteppedIo`, chosen in `09-seeing-the-ui:04-demo-in-browser`'s worker part: its clocks read the page's instant, and the tour's tasks take turns on a fixed set of threads, each a worker on the tour's shared memory, one at a time and only while the frame waits for them, so the worker draws on the page's clock exactly the frames the tour draws natively on the same ticks, which `test-demo` checks byte for byte. A worker per loader was the other option: without shared memory it cannot reach the sources and loads the loaders write, so the tour's loaders would have been rewritten around messages, and with it, it is the same threads without the turns that keep frames alike. Its cost is a page served cross-origin isolated |
